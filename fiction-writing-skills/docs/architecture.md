# 架构与模块选择

|能力|载体|理由与边界|
|---|---|---|
|世界规则、关系、知识、能力、创作记忆|fiction-canon Skill +记录模板|这些问题共享事实身份/生效时间/谁知道的约束；能力设计仅边界建模，无数值求解器，不再拆出重复Skill|
|事件与角色作用|fiction-outline Skill|独立输出可确认版本，不直接生成正文|
|设定及场景一致性|fiction-scene-audit Skill|需要语境推理、原文证据与分级，不能用关键词或计数代替|
|叙事表达|fiction-voice-revision Skill|作者提供/确认风格依据，不能把来源作者偏好固定为普遍文风|
|版本与章末事实|fiction-chapter-closeout Skill|将模型判断与文件快照、复制校验、断点恢复衔接|
|外部写作与多阶段协作|Markdown工作流和角色模板|明确输入/阶段/权限/交接；本版无常驻编排器|
|哈希、引用、白名单和发布构建|Python程序|确定性操作值得自动化；语义审稿仍由人或模型执行|

Skill目录各自自包含，仓库工具不是隐藏依赖。关系记录有方向、时间和不同维度，知识记录追踪渠道。规划层不进入已发生状态；核心设定变更先按作者授权确认，旧通过报告对更改后版本失效。

三种状态分开：候选稿、审查通过的固定稿、作者接受的发表稿。工具中的finalize仅固定审查通过的字节副本，绝不等于作者审美批准或平台发布。程序不认证是谁填写了报告；它拒绝缺字段与明显不满足契约的记录。

规范参考：[Agent Skills specification](https://agentskills.io/specification)（2026-11-06查阅）。使用最小name/description字段，不复制规范正文，也不引入实验性工具授权字段。Skill Creator的校验与本项目校验不是语义质量证明。
