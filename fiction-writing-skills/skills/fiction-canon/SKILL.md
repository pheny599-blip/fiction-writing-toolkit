# 设定与状态台账

## 输入

作者本轮目标、已确认规则/来源、采用正文及章末状态；只有点子时也可建立候选区。记录有效分支和时间，不凭“最新文件”推定正史。使用 [记录契约](references/template.md)。

## 执行

1. 分开世界规则、已发生正文、批准既有背景、后续计划、人物猜测和待确认提议。为每项保留ID、出处/位置、生效阶段、确认状态；内容相冲突时展示矛盾和影响，按作者既有明确授权处理，仍不明则留待决定。
2. 世界构建只补当前任务需要的规则与社会后果。缺失机制给选项，不伪造“原有设定”；只在明确授权范围内提交正史变更。
3. 关系按双方记录期待、熟悉、信任、秘密知情、人情与边界。不因认识、帮忙、外向或后台旧交自动获得秘密/权限。计划中的亲近须经事件发生，记录谁何时通过何渠道知道。
4. 能力/科技/法术可选同一约束卡：可观察效果、前置条件、范围/持续、代价、失败方式、已掌握、远期方向及知情层。不可为配角随意突破项目已确认的能力集合；不要求其他作者也采用封闭集合。
5. 新配角固定ID、关注、当场欲求、拒绝/受反馈方式；复现时延续状态，不重新随机人格。类型标签仅作灵感，不能代替人或科学结论。
6. 从通过稿提取章末状态时逐项链接正文；推测保留为推测，后台设定不冒充本章事件。下一章同时读状态与前文结尾，不能只靠摘要。

## 输出与异常

输出变更台账、关系/知识差异、能力边界及待确认区；不改正文。缺来源标“未验证”；来源截断先补读，不以猜测填空。若本次只整理候选设定，不得标已确认。参见 [独立虚构示例](references/example.md)。
