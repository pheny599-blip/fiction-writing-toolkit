# 章节交付与恢复

## 输入

指定候选稿、具体批准大纲、审稿报告与修复记录、输入来源版本、前章状态和作者确认依据。缺哪项就列缺口；不要从“成稿”文件名、修改时间或写作者自检推定通过。用 [交付契约](references/template.md)。

## 执行

1. 核对报告审的是当前候选稿，来源仍有效，覆盖完整，阻断与必要修改均关闭；身份按实际记录，单端不能冒称独立。可选建议不应触发无限返修。
2. 作者批准针对具体大纲及重大变更；已有授权不重复请求。报告通过、作者审美接受和对外发布分开记录，没有作者批准不能虚构批准记录。演示授权仅适用于该虚构案例，不能转作真实作者批准；记录绑定版本或哈希，后续改版不自动沿用。审查通过也不授权对外上传。
3. 将报告指定版本原样复制为新的固定稿，比较字节哈希。不得复制后悄悄润色；文字改变后重新审查受影响内容，旧报告不能用于新版本。
4. 从固定稿生成章末状态：时地、未完动作、身体资源、物件、目的情绪、关系边界、知识渠道和待承接事项，每项注明正文证据。猜测仍为猜测，规划不变事实。未写明的物件终态或情绪可以记未知，不为填满模板补写动作或推定无伤。
5. 记录当前阶段、输入输出版本、已用复审轮数、未解问题、唯一编辑者、最近交接和下一步。中断时先核对文件完整性及旧编辑者已停止，部分文件保留但不作完成输入；失败重启新版本，不重置返修轮数。
6. 来源变化时识别影响、停止受影响在途任务，保留旧稿并标失效范围；更新批准边界并复审。只写本章交付，不自动启动下一章。

## 输出与异常

通过时交纯正文固定副本、单独状态和交接；未通过交候选稿及缺口，不能伪造成稿。可用仓库可选Python工具核对哈希/声明，但它不认证批准或语义质量；无程序时按相同契约手工核对。见 [示例](references/example.md)。
