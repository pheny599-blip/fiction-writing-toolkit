# 作者交接写作与集中审稿

默认轻量流程，写作者可以是作者本人或其选择的工具，不绑定服务、不自动代发消息。

1. 作者选定有效分支、前章结尾和目标；用canon梳理必要规则、人物完整条目、关系/知识/能力与禁揭内容。作者已授权的工作无需反复确认。
2. 用outline交付具体大纲版本；作者确认关键结果、选择与揭露范围后写正文。保存批准来源，不以沉默替代批准。
3. 作者提供最小交接包和实际原始材料给写作者。交接包包含版本、大纲、起始状态、原始依据范围、允许/禁止改变项。仅路径不能代替传入文件。卡片、记录与纯正文分开。
4. 作者回传指定版本；用scene-audit一次集中核对完整适用范围。声明单端审查，不能以外部自检替代。结构问题回写作者；已授权小修用voice-revision，保留旧稿及修订记录。
5. R0首次审查，默认R1—R3最多三个修订加复审周期，保留问题ID、复审轮数和全章影响检查。三轮仍有阻断/必要修改就交作者裁定。来源缺失是无法完成，不应补造“通过”。
6. closeout固定确切通过稿、提取有正文依据的章末状态。作者审美接受单独记录；不自动开始下一章或发布。

中断时读最后完整交接和进度，确认旧编辑者不再运行，核对输入快照，再恢复未完成阶段。来源或批准边界变化使旧报告失效，重新标候选并复审。

示例材料见[港闸案例](../examples/harbor/scenario.md)，角色提示见[模板](../templates/role-prompts.md)。这些步骤可单人执行；程序没有调度其他聊天的能力。
