# Repository maintenance

This is a public tooling repository, not a novel workspace. Keep private manuscripts, author profiles, source audits and credentials outside it. New examples must be independently invented.

Skills must work when their whole directory is copied independently. Keep reusable schemas in references, avoid hardcoded author voice or project canon. Do not imply delegation, networking or publication permission from skill invocation. One prose editor at a time; never label self-review as independent review.

Run the repository validator and unittest suite after code changes. Report semantic review separately from deterministic checks. Build releases from the exact allowlist only. Never automatically extend the allowlist or push a release. Any changed release file invalidates a prior approval of its hashes.
